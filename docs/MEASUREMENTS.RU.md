# Запись и калибровка цикла сушки

[English version](MEASUREMENTS.md) · [Архитектура](ARCHITECTURE.RU.md) ·
[Обзор проекта](../README.RU.md)

Инструменты телеметрии записывают работающее устройство и строят график по
исходным отсчётам JSONL. Полезная запись включает прогрев, активную сушку,
вентиляцию и переход в `Hold`. По этим данным можно калибровать порог выделения
влаги отдельно от калибровки весов.

## Условия эксперимента

Каждому эксперименту соответствует свой каталог, например `runs/pla-01/`.
В ручном файле `experiment.md` рядом с записью сохраняются:

- материал, производитель, номер катушки, масса пластика и катушки;
- исходное состояние филамента и его подготовка;
- устройство камеры, положения датчиков, число катушек и условия в помещении;
- коммит загруженной прошивки, её версия и выбранный пресет;
- изменения стенда, открытия крышки и другие наблюдения со временем;
- независимый способ оценки сухости, если он используется.

Версию устройство сообщает через API. Коммит прошивки записывается по сборке,
использованной в эксперименте; `/api/state` его не возвращает. Фотографии
собранного устройства и панели могут сопровождать этот же эксперимент.

## Запись полного состояния

Для закреплённой зависимости построения графиков нужен Python 3.11 или новее.
Сама запись использует стандартную библиотеку Python. Из корня репозитория:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r tools/requirements.txt
python tools/telemetry.py capture --base-url http://dryer.local --duration 36000 --interval 5 --output runs/pla-01
```

В Windows команда активации — `.venv\Scripts\Activate.ps1`. Вместо
`dryer.local` можно указать IP-адрес. Если на панели включён вход по паролю,
параметр `--username admin` запрашивает пароль отдельно, без передачи в командной
строке.

Пример записывает до десяти часов. Запись начинается перед запуском режима на
устройстве или панели; длительности должно хватать на выбранный пресет и период
хранения. `Ctrl+C` завершает запись и сохраняет накопленные отсчёты. Существующий
каталог записи защищён от случайной перезаписи.

Сборщик использует только GET-запросы и создаёт:

| Файл | Содержимое |
|---|---|
| `telemetry.jsonl` | полные ответы `/api/state`, по записи `{ts, state}` на строку |
| `config.json` | доступные настройки управления и список пресетов, без полей сети и входа |
| `metadata.json` | время записи, интервал, статус, число отсчётов и ошибок, версии и исходные настройки режима |

`ts` — время компьютера в UTC; внутри состояния остаётся время работы
устройства и его время после синхронизации. Временные ошибки запросов выводятся
в журнал, попытки продолжаются до конца заданного периода. Ошибка входа
останавливает запись.

Записи `tools/remote.ps1 watch` используют такой же формат `{ts, state}` и тоже
подходят для графиков. `/api/history` устройства имеет другой, сокращённый
формат: отсчёты раз в минуту, ротация файла, без фазы сушки и числа спокойных окон.
Запись полного состояния сохраняет сведения, нужные для объяснения перехода в
`Hold`.

## График и разбор цикла

Команда построения экспортирует PNG или SVG:

```sh
python tools/telemetry.py plot runs/pla-01/telemetry.jsonl --output runs/pla-01/cycle.png
python tools/telemetry.py plot runs/pla-01/telemetry.jsonl --output runs/pla-01/cycle.svg
```

График объединяет температуры воздуха и нагревателя, абсолютную влажность и её
наклон с порогом. Полосы фаз отмечают продувку, стабилизацию и `Hold`. Невалидные
показания датчиков, недостаточное число отсчётов наклона, пропуски наблюдений и
перезапуски устройства оставляют разрывы без интерполяции.

Для разбора используются следующие поля:

| Сигнал | Поле `/api/state` |
|---|---|
| Температура камеры | `air.temperatureC`, `air.valid` |
| Температура и уставка нагревателя | `heater.temperatureC`, `heater.valid`, `outputs.heaterSetpointC` |
| Абсолютная влажность | `air.absoluteHumidityGm3` |
| Наклон и число отсчётов | `dryness.ahSlopeGm3PerHour`, `dryness.ahSlopeSamples` |
| Порог и спокойные окна | `dryness.slopeThreshold`, `dryness.stableWindows` |
| Фаза вентиляции | `dryness.purgePhase`: 0 закрыта, 1 стабилизация, 2 продувка |
| Фаза сушки/хранения | `phase` |

Нулевой наклон при числе отсчётов меньше восьми ещё не означает завершённого
измерения. Изменения `stableWindows`, минимальная/максимальная длительность и
`phase` позволяют разобрать переход в `Hold` по критерию пресета или по времени.

## Калибровка критерия сушки

Начальный порог — 0,3 г/м³/ч. Отчёт калибровки сопоставляет наклоны подходящих
закрытых окон в начале и конце нескольких циклов с независимой оценкой сухости.
В нём фиксируются предложенный порог, минимальное время и наблюдения,
обосновывающие оба значения.

Выбранные параметры затем проверяются в новом цикле, включая переход к хранению.
Отдельная запись может охватывать открытие крышки или замену катушки после
спокойного окна `Hold`, чтобы проверить автоматическую досушку. Для каждого
цикла сохраняются исходный JSONL, конфигурация, коммит прошивки, графики и заметки.

Пороги и времена пресетов заданы в
[AppConfig.cpp](../src/config/AppConfig.cpp). API возвращает их для просмотра;
изменение требует новой сборки прошивки. Температурная стабилизация и правила
измерительных окон описаны в [архитектуре](ARCHITECTURE.RU.md).

## Калибровка двух весов

Локальное меню `CALIB` и раздел калибровки веб-панели используют общий сервис.
Эталонная масса позволяет выполнить три отдельные операции:

1. **Тара:** при пустых платформах `tare` сохраняет их смещения сырых показаний.
2. **Масштаб:** известная масса на выбранной платформе задаёт число отсчётов
   на грамм. Операция API — `scale`, с `spool` 0 или 1 и `knownGrams`.
3. **Температурный дрейф:** при `drift_start` эталонные массы остаются на
   платформах. Сервис нагревает и охлаждает камеру, каждые 30 секунд снимая сырые
   показания и температуру воздуха. `drift_cancel` отбрасывает частичный сеанс.

Цель нагрева для дрейфа — меньшее из 80 °C и настроенного потолка воздуха минус
2 °C (73 °C при исходном потолке). У каждого датчика 16 диапазонов шириной 5 °C
с началом в 20 °C; крайние температуры используют крайние диапазоны. Для
сохранения таблицы завершённому циклу нужны хотя бы три заполненных диапазона
и заполненный опорный диапазон. Авария или шестичасовой тайм-аут заканчивают
сеанс без сохранения новой таблицы.

`GET /api/calibration` возвращает фазу, число точек, сырые показания, масштабы и
сохранённые таблицы коэффициентов. Отчёт калибровки весов содержит эталонные
массы, условия помещения и показания до и после компенсации. Калибровка весов и
порога выделения влаги камеры — отдельные эксперименты.

## Публикация результатов

Завершённый пример с устройства состоит из условий, исходных записей,
конфигурации и графика. Синтетические данные тестов проверяют инструменты и не
являются измерениями устройства. Записи реальных циклов и откалиброванный порог
можно добавить сюда после описанных экспериментов.
